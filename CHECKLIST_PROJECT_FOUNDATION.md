## Migrated From Main Checklist: Ground Rules

- [x] Define the target as Minecraft Java Edition 26.1.2 protocol and server behavior.
- [x] Keep the new implementation independent of Mojang source code licensing constraints. — `docs/COMPATIBILITY.md` documents the no-copying boundary, `build.rs` treats the local Java decompilation tree as an optional parity oracle (`vibecraft_has_decompiled_sources` / `vibecraft_has_sound_events_source`) instead of a required build input, and hidden-source verification passes: temporarily moving `../decompiled-server-26.1.2` aside allows `cargo check` and `cargo test --no-run` to compile successfully with only optional-source warnings.
- [x] Use black-box tests, public protocol references, vanilla datapacks, generated assets, and observed behavior as validation sources. — `docs/VALIDATION_SOURCES.md` defines the allowed evidence families and precedence; `project_foundation_tests::validation_sources_policy_names_each_allowed_evidence_family` verifies checked-in hooks for Mineflayer/raw black-box tests, prismarine/`minecraft-data` protocol references, `vanilla-data` datapack resources, generated Rust/report assets, and observed packet/log/artifact behavior.
- [x] Track every intentional deviation from vanilla behavior in a compatibility document. — `docs/COMPATIBILITY.md` owns the intentional-deviation list and currently records the unsupported Swing GUI, chase debug server/client, and native-transport implementation decision.
- [x] Build a repeatable test harness that can compare the rebuilt server against the official `server.jar`. — `harness/mineflayer/runner.mjs::runParityScenario` starts official `server.jar` and VibeCraft in separate temp worlds with shared offline server files, normalizes volatile artifacts, and diffs observable events/logs/properties; `runner.test.mjs` passes (8 tests), and `project_foundation_tests::mineflayer_runner_targets_vibecraft_and_official_server` verifies the foundation wiring.
- [x] Add Mineflayer-based black-box smoke tests that can target either VibeCraft or the official `server.jar`.
- [x] Add a Mineflayer fixture that records bot event order, disconnect reasons, kicked messages, and packet-level errors for every black-box scenario. — `harness/mineflayer/login_session.mjs` provides the shared `runObservedOfflineLogin` / `captureObservedBotEvents` fixture used by black-box scenarios; it records ordered bot events, kicked-message summaries, packet traces, server-log slices, cleanup handles, and packet/client errors as `client_error` trace entries plus `packet_error` timeline events. `node --test harness/mineflayer/login_session.test.mjs` passes (4 tests).
- [x] Add a Mineflayer offline-mode baseline scenario shared by all black-box tests, including deterministic bot names, expected offline UUIDs, seeded temp worlds, fixed ports, and vanilla comparison output. — `harness/mineflayer/offline_baseline.mjs` builds the reusable offline-mode baseline from shared fixtures: deterministic bot names, vanilla offline UUIDs, seed `8675309`, fixed port `25565`, offline `server.properties`, required packet-capture states, and vanilla comparison artifact output. `node --test harness/mineflayer/offline_baseline.test.mjs` passes (2 tests).
- [x] Add a Mineflayer offline-mode login contract test that every black-box suite can reuse to assert server readiness, EULA acceptance, deterministic profile creation, and successful play-state entry before running scenario-specific assertions. — `harness/mineflayer/offline_login_contract.mjs` wraps the shared observed-login fixture and exposes reusable assertions for server readiness, `eula=true`, offline `server.properties`, deterministic vanilla offline UUIDs, and play-state spawn entry before scenario assertions. `node --test harness/mineflayer/offline_login_contract.test.mjs` passes (3 tests).
- [x] Add a Mineflayer offline-mode login artifact test that captures `server.properties`, `eula.txt`, `usercache.json`, playerdata paths, bot UUIDs, and normalized vanilla/VibeCraft log lines for each baseline run. — `harness/mineflayer/login_artifacts.mjs` collects baseline login artifacts, bot/expected UUIDs, usercache, playerdata paths, normalized logs, and official-vs-VibeCraft log diffs; `login_artifacts.test.mjs` verifies all required surfaces and volatile-only normalization. `node --test harness/mineflayer/login_artifacts.test.mjs` passes (3 tests).
- [x] Add Mineflayer parity snapshots for the offline-mode happy path that preserve raw bot events, packet names, server log excerpts, and normalized official-vs-VibeCraft diffs as test artifacts. — `harness/mineflayer/offline_parity_snapshot.mjs` preserves raw event timelines, packet names, server log excerpts, normalized session artifacts, and normalized official-vs-VibeCraft diffs for the offline happy path. `node --test harness/mineflayer/offline_parity_snapshot.test.mjs` passes (2 tests).
- [x] Add a Mineflayer offline-mode preflight test that fails fast with actionable artifacts when the server never opens the port, never reaches login success, or disconnects before configuration completes. — `harness/mineflayer/offline_preflight.mjs` wraps the minimal CI login shard, requires diagnostics/artifacts on stalled readiness/login/configuration milestones, and reports actionable failure reasons; `offline_preflight.test.mjs` passes.
- [x] Add a Mineflayer offline-mode version-lock test that verifies the configured Mineflayer/prismarine protocol version matches Minecraft Java Edition 26.1.2 before any black-box scenario runs.
- [x] Add a Mineflayer offline-mode login diagnostics contract requiring every black-box failure to include bot username, expected UUID, server PID, port, last packet, last bot event, and normalized disconnect component. — `harness/mineflayer/offline_login_diagnostics.mjs` builds and validates the required diagnostic envelope for black-box login failures, including normalized kicked/disconnect components. `node --test harness/mineflayer/offline_login_diagnostics.test.mjs` passes (2 tests).
- [x] Add a Mineflayer offline-mode baseline comparison test that runs the same generated bot profile against vanilla first, stores the accepted event timeline, then reuses it as the VibeCraft assertion envelope. — `harness/mineflayer/offline_baseline_comparison.mjs` runs official first, stores event/packet-name envelopes, then compares VibeCraft against that accepted oracle before producing the parity snapshot; `offline_baseline_comparison.test.mjs` passes.
- [x] Add a Mineflayer offline-mode matrix owner test that requires every black-box scenario touching login to declare whether it uses fresh profile, returning profile, duplicate profile, op profile, whitelisted profile, or banned profile fixtures. — `harness/mineflayer/offline_matrix_owner.mjs` declares/lints the six required login fixture kinds (`fresh`, `returning`, `duplicate`, `op`, `whitelisted`, `banned`) and reports fixture coverage; `offline_matrix_owner.test.mjs` passes.
- [x] Add a Mineflayer offline-mode vanilla-oracle freshness test that reruns the official `server.jar` baseline when the Mineflayer/prismarine version, protocol version, server jar, or scenario fixture changes. — `harness/mineflayer/offline_oracle_freshness.mjs` keys freshness on Mineflayer version, prismarine-protocol version, protocol version, `server.jar` SHA-256, and scenario fixture hash, requiring rerun on any drift; `offline_oracle_freshness.test.mjs` passes.
- [x] Add a Mineflayer offline-mode fixture sanity test that proves each generated bot username maps to the expected UUID before server start, after vanilla login, and after VibeCraft login. — `harness/mineflayer/offline_fixture_sanity.mjs` checks Java offline UUID derivation (`OfflinePlayer:<name>` via the shared `offlineUuid`) before start and against vanilla/VibeCraft observations; `offline_fixture_sanity.test.mjs` passes.
